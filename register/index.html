Participant directory

Register

Fill this in once for your organization, listing each piece of software you'll test. It builds your participant file and, from the button at the bottom, opens GitHub with the file filled in, ready to propose as a pull request. Everything you enter is public.

Where your entries appear

  • Every component is listed in the directory, where other teams find what to test against and whom to ask.
  • Web wallets also go into the wallet registry (wallets.json), because Verifier pages open them directly from their wallet menus. Only web wallets whose status is Up are included.
  • Native wallets aren't in the registry: the patient reaches them through the phone's own wallet chooser. They're listed in the directory with how testers get them, and you don't need a public build (see the native wallet example).
  • Verifiers are the side that asks for data. EHR check-in pages, patient portals, kiosks, and clinic apps register as Verifiers, with the role verifier. They're listed in the directory. A Verifier that is a phone app registers its platforms and how testers get it instead of a URL (see the Verifier examples).
Organization

Also names your file, as participants/<name>.json.

Contacts

Who testers reach during the event. At least one, each with a GitHub username, Slack display name, or email. All of it is public, so list only details you're happy to publish.

Include your GitHub username. A pull request from anyone listed here with a GitHub username merges automatically once the file passes the checks, and only they can change the file later. Without one, a maintainer reviews each change.

Components

Each piece of software others can test with you. An EHR's check-in page, patient portal, kiosk, or clinic app is a Verifier; a patient's health app is a wallet. Add one for each; a clinic with a web check-in page and an app adds two.
